### 阶段一 · 结果（已完成）

**1.1 ERROR 111 条** —— 102 条 `timeout after 25.0s`，集中在 10-22 14-17 点
（白天群活跃 4 小时贡献 84 条）。根因是**判定太频繁把 provider 打满**，不是链路问题。
其余：6 条 `ProviderNotFound`（**全部在 10-20 上午**，那时还没配 `judge_provider_id`，
10-20 10:25 之后再没出现过，历史问题已自愈）、2 条 502、1 条 429。

→ 处置：加 `max_per_hour`（默认 **60**，0 = 不限）。真上线也必须有这个限制，
  否则一小时几百次判定既烧钱又限流。回放里置 0 解除。

**1.2 PARSE_FAIL 8 条** —— **第三类根因**（前两类是换行、多余右括号）：
模型用**中文逗号**分隔 JSON 字段，或干脆写成**单引号的 Python 字典**。
→ 处置：抽出 `_loads_lenient()`，四级兜底：raw_decode → 引号间中文逗号修复
  （只改引号之间的，正文里的中文标点不动）→ `ast.literal_eval` → 放弃。
  `--selftest` 扩到 **7 条，7/7 通过**（含"真不是 JSON 仍要判失败"，防修过头）。

**1.3 REPLY 率** —— 4083 条里 4.3%，回放基线 5.8%、早期 419 条时 7.4%。
样本越大越趋稳，且新增样本含大量夜间/低活跃时段，属**样本效应不是退化**。
（真实 REPLY 抽样仍是实质增量：MODID 误填、ZWJ 零宽字符、穿透值作用等。）

**1.4 防护拦截 1 条** —— 真实群里确实触发了一次，待人工确认是否误伤（见下）。
