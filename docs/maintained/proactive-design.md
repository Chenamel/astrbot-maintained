# 主动回复插件设计（基于用户标注的场景基线）

> 来源：2026-10-20，用户对 10 个真实群聊场景逐条标注"该说/不该说/看情况"。
> 这份文档是**标准的唯一依据**——判定规则从这里推导，不从旧插件继承。

## 一、用户标注结果（原始基线）

| # | 场景 | 用户判断 | 关键补充 |
|---|---|---|---|
| 1 | 别人正在帮忙，中间插追问 | **不该**（不插嘴） | 有人已在服务 |
| 2 | 群内公开求助（看不到文件名闹乌龙） | **该说** | **必须把文件名+后缀解析进上下文**（不带文件内容，太重） |
| 3 | 纯图片 | **看氛围** | 图片是否被讨论决定 |
| 4 | 短回应「嗯」 | **看情况** | 若聊天有方向，可给总结建议或具体办法（如"清空配置是不错的办法"） |
| 5 | 冷场后一条纯图（无信息） | **不回** | 没信息 = 不回 |
| 6 | 被吐槽「机器人太叛逆了」 | **应急预案** | 道歉 + 静默，而不是普通回复 |
| 7 | 被逗/被点名玩 | **正常回** | 视为被叫 |
| 8 | 多人热烈聊 | **可以说** | ⚠️ **禁止豆包式纯情绪回复**（群友会觉得"糖"） |
| 9 | 长句闲聊陈述 | **可回可不回** | 按情况，倾向少说 |
| 10 | @ 别人提问 | **先不回** | 等被@的人说完 → 再接一句**自己的看法**，**且不 @ 他人** |

## 二、从标注推导的判定框架

### 该说（正向条件，满足其一且不被抑制）
- **P1 未响应的求助**：群里有人提出需求/问题，且**没有人正在处理**
- **P2 能提供实质增量**：知识、具体建议、总结性判断（不是"我也觉得"）
- **P3 被点名/被逗/被吐槽**：走专门通道（见下）
- **P4 补充位**：他人已回答完毕后，可补一句自己的看法

### 不该说（抑制条件，任一命中即闭嘴）
- **N1 已有人在服务**（他人在一对一帮忙、正在解答）← 场景 1
- **N2 信息缺失**（纯图无文、无实质内容、看不到关键上下文）← 场景 5
- **N3 自己没有实质可说的**（"可回可不回"时默认少说）← 场景 9
- **N4 刚被吐槽/投诉** → 进入静默期（见应急）
- **N5 正在被他人 @ 的对话进行中** → 排队等，不抢 ← 场景 10

### 风格红线（违反即"AI 味"）
- ❌ 纯情绪/廉价共情（"哈哈哈太有意思了""确实呢"）← 用户原话："豆包式…会被认为很糖"
- ❌ 主动 @ 他人（补充看法时不要 @）
- ✅ 带**具体信息**（文件名、版本、步骤）
- ✅ 有判断、有增量，或干脆不说

### 应急通道（场景 6）
被吐槽/投诉 → **道歉 + 进入静默期**（参考旧插件 `complaint_quiet_sec` 的思路，但由新插件自己实现）

## 三、上下文组装要求（关键，来自场景 2 的教训）

1. **文件名 + 后缀必须进上下文**，但**不带文件内容**（太重）
   —— 旧链路因看不到文件名闹过乌龙
2. 图像：按"是否被讨论/是否有文字伴随"决定要不要理解；**没有信息就当没看见**
3. 长程：不能只看最近 3 分钟（旧插件的 180 秒窗口已被证明不足）
   —— 待定：取最近 N 条 + 话题摘要 + livingmemory 语义召回
4. 引用/链接：至少保留"引用了谁、说了什么"的文本（链接抓取待评估）
5. **合并转发的真实边界（2026-10-21 实测修正）**：
   - core 自带引用提取链（astr_main_agent_quote → quoted_message_parser →
     extractor.py:43 → OneBot get_forward_msg，递归拉嵌套转发）
   - ⇒ **被引用的转发**：被动路径能拉到全文 ✅
   - ⇒ **裸发无人引用的转发**：被动/主动都看不到（LLM 只见 `[Forward]`）——
     这是 core 级限制，非主动回复独有
   - ⇒ 历史库（platform_message_history）只存 `[Forward]` 占位，转发 ID 丢失，
     事后无法补拉；影子插件只能在**实时事件**里当场展开（Forward 组件此刻仍在）
   - 内容提取层若做转发展开，应挂实时事件，两条路径同时受益

## 四、验证方式：影子模式（必做）

- 插件先**只判定不发送**，把每条判定（原文 + decision + reason）落盘
- 挂在活跃群（1105248343 / 827767299 / 715383308 每天都有流量）
- 跑几天后人工回看准确率，达标才开真发
- 好处：零打扰试错，且**不依赖有人 @ 机器人**

## 五、与现有插件的边界（上线前必须处理）

| 现有机制 | 处理 |
|---|---|
| `enhance_mode.active_reply` | 保持关闭（新插件接管） |
| `enhance_mode.followup` | 需评估是否关闭，避免两套同时说话 |
| `wake_enhance.continuous_awakening` | 需评估（窗口短但会绕过判定） |
| `livingmemory` | **复用**（记忆召回昨天已修复并验证） |
| `proactive_chat` | 运行时已禁用，保持 |
