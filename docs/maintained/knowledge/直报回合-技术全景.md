## 2. 数据结构

```python
@dataclass
class DirectTurn:
    first_at, last_at        # 聚合窗口边界
    events: list             # 本回合已收集的消息事件
    owner                    # 当前归属事件（对外视为"当前"的那条）
    version: int             # 每次新消息到达 +1
    sent: bool               # 是否已发出回复（发出后不再收集）
    closed: bool             # 回合是否关闭
    changed: asyncio.Event   # collect 的唤醒信号
    tools: dict              # (name, normalized_params) -> 工具执行/结果槽位

class DirectTurnCoordinator:   # 模块级单例 coordinator = DirectTurnCoordinator()
    __init__(clock=time.monotonic, quiet_sec=4, max_wait_sec=15)
    turns: dict                # umo -> DirectTurn
    proactive: dict            # umo -> (runner_event, runner.request_stop)
```

**回合键**：`(unified_msg_origin, sender_id)`。
**窗口**：`min(first_at + max_wait_sec, last_at + quiet_sec)`。

## 3. 状态流转

```
        observe(event)                    collect(event)             prepare(event)
  ┌─────────────────┐  等静默/超时  ┌────────────────────┐  定 owner  ┌──────────────┐
  │ 收集中           │ ───────────▶ │ 已关闭，返回 owner  │ ────────▶ │ 已就绪        │
  │ version = N      │              │ version 仍 = N      │           │ 注入 req extra │
  └────────┬─────────┘              └────────────────────┘           └───────┬──────┘
           │ 期间又来新消息                                                     │
           ▼ version = N+1，旧 owner 事件被置：                                  │
   `_turn_superseded=True` + `agent_stop_requested` + `stop_event()`              │
   + 调 `proactive[umo][1]()`（即 runner.request_stop）                            │
                                                                                 ▼
                                                            出站门禁 is_current() / mark_sent()
                                                                                 │
                                                          scheduler.finally: coordinator.finish(event)
```

## 4. 对外契约（core 内与插件可见的符号）

| 符号 | 语义 |
|---|---|
| `is_current(event)` | 该事件是否仍代表当前回合（未 superseded、版本一致、未关闭）。无回合信息时**返回 True**（非目标平台自然短路） |
| `mark_sent(event)` | 标记回合已发出回复，此后不再收集新消息 |
| `begin_tool / record_tool_result / get_tool_result / release_tool` | 工具结果复用协议：占位 → 记录 → 读取 → 释放 |
| `wait_tool_result` | 等待他人正在执行的同参工具结果，**超时 15s** 返回 `"Previous operation may already have executed. Do not repeat it; completion is unconfirmed."` |
| `observe / collect / prepare / finish / reset / reset_all` | 生命周期 |

**event extra 键**（写入方 → 读取方）：

| 键 | 写入 | 读取 |
|---|---|---|
| `_direct_turn_state` / `_direct_turn_version` | `observe` | `internal.py`（抑制流式、抑制追问捕获） |
| `_direct_turn_text` | `prepare` | `internal.py`（合并注入 `req.prompt`） |
| `_direct_turn_image_urls` | `prepare`（去重取前 **2** 个，**仅 URL 字符串，不下载**） | `internal.py` |
| `_direct_turn_task_text` | `prepare`（后 16000 字符） | `code_delivery_policy.code_task_spec` |
| `_turn_superseded` / `agent_stop_requested` | 取代旧轮次时 | `is_current` / 各门禁 |

## 5. 运行方式与配置边界

- **无持久化**：全部状态在进程内存（`self.turns` / `self.proactive` 字典），重启即清空。
- **无 I/O**：不读不写实例文件、不读配置（`wake_prefix` 由 `scheduler.py` 从 `astrbot_config` 传入）。
- **平台边界**：`eligible()` 判定 `platform_name() == "aiocqhttp"` 且存在 sender。

## 6. 风险

| # | 风险 | 说明 |
|---|---|---|
| R1 | **平台硬编码** | `aiocqhttp` 字符串写死在 `eligible()`，其他平台无法复用合并能力 |
| R2 | **模块级单例状态泄漏** | `self.turns` / `self.proactive` 无 TTL 兜底；若 `finish` 在异常路径未调用，key 永久驻留（现仅靠 `first_at + max_wait_sec` 被动过期） |
| R3 | **取消不保证真中断** | 协作式取消；provider 流式不响应 `stop_event` 时 token 仍消耗，仅产物被丢弃 |
| R4 | **无锁** | `changed` Event 与 `version` 自增在多协程间共享，依赖"无 await 临界区"的隐式假设 |
| R5 | **可观测性弱** | 关键状态迁移（回合被取代）无 debug 日志；`is_current` 短路处静默 return |
| R6 | **魔法数字散落** | `quiet_sec=4` / `max_wait_sec=15` / `wait_tool_result` 15s / 图片上限 2 / 文本 16000 / events 上限 30 / poll 0.25s |
| R7 | 与上游风格偏差 | 模块级可变单例更接近"服务/注册表"，与 core `utils/` 多为无状态纯函数的风格不一致 |
