# 图片不可用降级 · 业务流程

> 所属业务线：交付保障。本文只讲"用户侧看到什么"，不展开代码。

## 1. 目标与范围

**目标**：当用户发了图、但模型实际拿不到可用视觉内容时，给出**确定性**的答复，绝不编造图片内容。

**范围**：所有平台的图片输入路径（触发点在 provider 传输层，不限于 QQ）。

## 2. 输入、输出与参与方

| 项 | 内容 |
|---|---|
| 输入 | 用户消息 + 图片（URL 或本地引用）+ 可能的文字提问 |
| 输出 | ① 正常：基于图片内容的回答；② 降级：固定文案"当前看不到图片，请重新发送。" |
| 参与方 | 用户、图片描述服务、provider、Agent runner |

## 3. 端到端流程

```
用户发图 + "这图里写了什么"
        │
        ▼
   能不能拿到视觉证据？
        │
   ┌────┴─────────────────────────┐
   │ 能                            │ 不能
   ▼                               ▼
原生图 URL 送入模型            图片描述（caption）也失败
或生成 <image_caption>         ↓
   │                           摘掉全部工具（避免盲操作）
   ▼                           注入模型侧指令：
正常回答                        "没有视觉证据，禁止从历史/文件名/上下文推断"
                                ↓
                           用户收到固定文案
                           "当前看不到图片，请重新发送。"
```

## 4. 什么时候会"看不到图"

| 原因 | 典型场景 |
|---|---|
| 模型不是视觉模型（not VLM） | 用了纯文本模型却发了图 |
| 图片上传被内容审核拦截 | 平台侧审核拒绝 |
| 附件失效 | URL 404、下载失败 |
| 图片描述服务本身失败 | caption 生成异常或返回空 |

## 5. 状态与规则

| 规则 | 业务含义 |
|---|---|
| **看不到就说看不到** | 固定中文文案，不猜、不糊弄 |
| **不许从历史/文件名/上下文推断** | 模型侧被明确告知：不能说"根据文件名推测…" |
| **看不到图时不调工具** | 避免"盲操作"产生错误副作用 |
| **失败标记不污染后续** | 历史里失败过一次，不影响之后带图的正常请求 |
| **只对"确实请求了图片"的请求生效** | 纯文本请求不会被历史失败标记误伤 |

## 6. 异常与边界

| 场景 | 表现 |
|---|---|
| 用户只说"看这个"但不发图 | 不走本链路（未请求图片） |
| 降级后用户重新发图 | 正常走视觉路径（状态复位） |
| 历史里残留失败标记 | 新一轮带图/描述即复位，不延续 |
| 降级发生在流式输出中 | 已缓冲的 chunk 被整体替换为固定文案（不会只发一半） |
