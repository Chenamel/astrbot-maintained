# 交付保障 · 业务全景

## 1. 为什么有这条链路

三个"用户一眼就能看出机器人坏了"的场景：

| 场景 | 用户看到 | 本质 |
|---|---|---|
| **空交付** | 用户说"写个脚本"，模型回一大段"你可以这样写：首先…其次…"，**就是没有代码** | 模型把"解释方案"当交付 |
| **失败刷屏** | 同一个工具用同一组参数反复失败，机器人试十几遍 | 无熔断，模型看不到"你已经失败过了"的有效信号 |
| **看图编内容** | 用户发图，模型实际拿不到图，却根据文件名/历史/上下文**编**出图里有什么 | 缺"我看不到"的确定性降级 |

## 2. 参与方与术语

| 术语 | 含义 |
|---|---|
| **交付（delivery）** | 模型最终给用户的成品；代码任务下必须是**可用的源码** |
| **空交付** | 声称完成但正文里没有可用的代码块 |
| **交付修复** | 检测到空交付后，**自动再问一次**模型要源码（单次，不循环） |
| **失败熔断** | 同参工具连续失败达阈值（`REPEATED_TOOL_FAILURE_LIMIT = 3`）后，屏蔽该工具并收尾作答 |
| **视觉证据** | 本次请求里真实可用的图片内容（原生图 URL 或图片描述 `<image_caption>`） |
| **图片不可用** | 标记 `image_input_unavailable`：模型被明确告知"没有视觉证据，不许推断" |

## 3. 能力地图

```
交付保障
   ├── 空交付检测与修复        → 要代码必须真给代码
   ├── 同参工具失败熔断        → 不刷屏，失败要能收敛
   ├── 图片不可用确定性降级    → 看不到就说看不到，禁止幻觉
   └── 执行授权策略            → 只摘掉不该用的工具（详见"执行授权"文档）
```

## 4. 端到端流程（用户视角）

**代码任务**
1. 用户："帮我写个读取 csv 的脚本"
2. 模型回："可以这样写，首先导入 pandas…"（无代码块）
3. 系统识别到"这是代码任务 + 没有交付源码 + 不是安全拒答" → **自动追加一次校正请求**
4. 模型补上真正的代码块，交付给用户
5. （若修复后仍无代码 → 放行原文并置 `CODE_DELIVERY_FAILURE = "这次没生成完整代码，可以再试一次"`，**只修一次**）

**图片不可用**
1. 用户发图 + "这图里写了什么"
2. 图片处理失败（模型不支持视觉 / 上传被审核 / 附件失效）
3. 系统**摘掉全部工具** + 注入模型侧指令"没有视觉证据，禁止从历史/文件名/上下文推断"
4. 用户收到固定文案：**"当前看不到图片，请重新发送。"**

## 5. 通用规则与边界

| 规则 | 说明 |
|---|---|
| 修复**只做一次** | `_code_repair_attempted` 单次短路；不做多轮自纠，避免延迟与成本失控 |
| 修复**不覆盖安全拒答** | 命中 `SAFETY_REFUSAL_PATTERN` 不修复（模型拒绝是正当行为） |
| 修复**不覆盖图片不可用** | 图片场景有自己的降级路径 |
| 熔断**按参数精确匹配** | 键为 `(工具名, 参数标准化后 JSON)`；**参数不同则重新计数** |
| 图片不可用**摘工具** | 没有视觉证据时不允许再调工具，避免"盲操作" |
| 历史里的失败标记**不污染后续** | 新一轮只要带了图或描述，就复位为"可用" |

## 6. 明确不做什么

- 不做多轮代码自纠、不做代码正确性校验（只判"有没有交付源码"）。
- 不做安全审查（`SAFETY_REFUSAL_PATTERN` 仅用于**跳过修复**，不是内容安全兜底）。
- 不做图片 OCR 兜底（拿不到就是拿不到，不猜）。
- 不做跨工具的统一重试策略（熔断只针对"同参重复失败"）。
