## 1. 模块与职责

| 位置 | 角色 |
|---|---|
| `astrbot/core/code_delivery_policy.py` | **判定层**：执行授权 + 代码任务识别 + 源码交付校验 |
| `agent/runners/tool_loop_agent_runner.py` | **执行中枢**：交付修复、失败熔断、图片短路、轮次门禁 |
| `provider/entities.py` | **数据契约**：`IMAGE_INPUT_UNAVAILABLE_MESSAGE/NOTICE` + 双向布尔字段 |
| `provider/sources/openai_source.py` | **传输层容错**：图片不可用时摘工具、注入声明、回归固定文案 |
| `agent_sub_stages/image_input.py` | **视觉证据判定**：写 `req.image_input_unavailable` |
| `astr_main_agent.py` | 图片描述降级；请求装配末尾挂载 `apply_execution_policy` |
| `astr_agent_run_util.py` | 交付闸门（见"直报回合"） |

## 2. 数据模型（契约）

```python
# provider/entities.py
IMAGE_INPUT_UNAVAILABLE_MESSAGE = "当前看不到图片，请重新发送。"     # 给用户
IMAGE_INPUT_UNAVAILABLE_NOTICE  = (                                  # 给模型
    "[Image unavailable: no visual evidence was received. "
    "Do not infer or describe the image from history, filenames or surrounding text. "
    f"Reply only: {IMAGE_INPUT_UNAVAILABLE_MESSAGE}]")

ProviderRequest.image_input_unavailable: bool = False   # 新增
LLMResponse.image_input_unavailable:     bool = False   # 新增 + 构造器参数
```

**隐式协议**：`"<image_caption>"` 标记（**5 处硬编码**，无共享常量）——见 §6 P4。

## 3. 三条链路

### 3.1 空交付检测与修复（runner 内）

```
_complete_with_assistant_response
  task = code_task_spec(event)                       # 读 _direct_turn_task_text 优先
  if task 且 not has_code_delivery(text, task[1])
     且 not SAFETY_REFUSAL_PATTERN.search(text)
     且 not image_input_unavailable
     且 not self._code_repair_attempted:
         self._code_repair_attempted = True          # 单次，不重试
         追加用户消息 "[Source delivery correction] ..."
         asyncio.wait_for(provider.text_chat(...), timeout=30)
         清空 tools_call_* 与 reasoning 字段
         logger.info("Code delivery repair message_id=%s language=%s outcome=%s", ...)
```

`has_code_delivery` 判据：围栏代码块非空 **且** 语言匹配/可推断（`cpp`/`python`）**且** 正文不含 `...`/`…` 的省略式伪代码。
超时/异常 → `completion_text = CODE_DELIVERY_FAILURE`。

### 3.2 同参工具失败熔断（runner 内）

```
failure_key = (tool_name, json.dumps(normalized_params, sort_keys=True, default=str))
每次失败：_same_tool_failure_streak += 1（同键连续）
达 REPEATED_TOOL_FAILURE_LIMIT(=3)：
    加入 _blocked_failed_tool_keys，写 _tool_failure_summary
    历史 tool 消息改写为 "error: Repeated identical tool failure (details in final summary)."
_step 检测到 _tool_failure_summary 非空：
    req.func_tool = None；_skill_like_raw_tool_set = None；_tool_schema_param_set = None
    追加 "[Tool failure limit]..." 用户消息 → 一次 30s 超时最终生成
```

### 3.3 图片不可用确定性降级（四阶段）

| 阶段 | 位置 | 相对钩子 | 动作 |
|---|---|---|---|
| ① | `astr_main_agent._ensure_img_caption` | **`on_llm_request` 之前** | 描述失败 → `image_input_unavailable=True`、`func_tool=None`、追加 `NOTICE` |
| ② | 插件的 `on_llm_request` | 钩子中 | 若有图/描述则复位并**反向过滤** `NOTICE` 部件 |
| ③ | `image_input.prepare_request_images` | 钩子**之后** | 依据 `parts` 重新判定并写 `_enhance_visual_unavailable` |
| ④ | `openai_source` | provider 调用期 | 转换层补追加 `NOTICE`；历史回读判定；产出 `MESSAGE` 固定文案 |

**provider 侧触发条件**（三者之一，且需 `not image_fallback_used and _context_contains_image(...)`）：

| 触发 | reason |
|---|---|
| `"The model is not a VLM" in str(e)` | `model_not_vlm` |
| `_is_content_moderated_upload_error(e)` | `image_content_moderated` |
| `_is_invalid_attachment_error(e)`（`code == invalid_attachment` / 含 `download attachment` + `404`） | `invalid_attachment` |

回退动作：`_remove_image_from_context`（deepcopy 去图，空内容补 `NOTICE`）→ 追加 `{"role":"system","content": NOTICE}` → `payloads.pop("tools"/"tool_choice"/"parallel_tool_calls")` → `func_tool = None`。
流式：`buffer_images` 为真时对每个 chunk `copy.deepcopy` 缓存（`_query_stream` **复用同一个 chunk 对象**），降级则整体替换为固定文案并保留 `usage`。

## 4. 对外契约

| 符号 | 可见性 | 说明 |
|---|---|---|
| `IMAGE_INPUT_UNAVAILABLE_MESSAGE` / `NOTICE` | core 三处 + 存量插件一处消费 | **应上移 `astrbot.api.provider`**（见 inventory §3.3） |
| `code_task_spec` / `has_code_delivery` / `CODE_DELIVERY_FAILURE` | 纯函数 | 可上移供插件复用 |
| `EXECUTION_TOOL_NAMES` | core 内部 | 硬编码 4 个工具名 → 应改为工具自行声明 |
| `SAFETY_REFUSAL_PATTERN` | core 内部 | 仅用于**跳过修复**，非内容安全 |

## 5. 运行方式与配置边界

- `execution_denial` 只读配置（`config["admins_id"]`），不写配置、不落盘。
- 交付修复会产生一次额外 LLM 调用（`timeout=30`），是**可观测的成本项**。
- 图片降级路径**无任何日志**（`openai_source.py` 新增代码零日志）——重要行为不可观测。

## 6. 风险

| # | 风险 | 说明 |
|---|---|---|
| P4 | `"<image_caption>"` 5 处硬编码 | entities / image_input / openai_source×2 / astr_main_agent，改一处漏一处 |
| — | 熔断按"同键**连续**"计数 | 模型交替调用 A/B 两个失败工具则永不触发 |
| — | 修复只试一次且无二次校验 | 修复后仍无代码块即放行空交付 |
| — | 降级无日志 | `_fallback_to_text_only_and_retry` 的 reason 有日志，新增分支无 |
| — | 深拷贝开销 | 图片场景对每个 stream chunk `deepcopy`，且缓冲使流式失去实时性 |
| — | 参数键不稳定 | `failure_key` 依赖 `json.dumps(default=str)`，含不可序列化对象时键可能不稳定 |
| — | `preserve_native_images` 为死参数 | core 内无生产调用点（仅测试使用） |
| — | 三处重复摘工具 | entities 转换方法 / `_ensure_img_caption` / `_fallback_to_text_only_and_retry` |
| — | 顺序错配竞写 | `req.image_input_unavailable` 被阶段①③与插件②三方写入，最终值取决于③ |
| — | `_decorate_llm_request` 移除 `if req.conversation:` 守卫 | 无会话上下文时也会尝试图片描述，扩大触发面 |
| — | 中文正则启发式 | `execution_denial` 双向误判（误放行=提权风险 / 误拒绝=功能不可用） |
