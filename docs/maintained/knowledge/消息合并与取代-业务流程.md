# 消息合并与取代 · 业务流程

> 所属业务线：直报回合。本文只讲"谁在什么时候看到什么"，不展开代码。

## 1. 目标与范围

**目标**：让同一账号的连发消息被当作一个请求处理，并且旧请求的结果不会污染新请求。

**范围**：仅 `aiocqhttp`（QQ）平台、有发送者的会话。其他平台行为完全不变。

## 2. 输入、输出与参与方

| 项 | 内容 |
|---|---|
| 输入 | 同一 `(会话, 发送者)` 在时间窗内到达的 N 条消息（含图片、引用、@） |
| 输出 | **一次**回复（针对最新一条完整诉求）；旧轮次产物被静默丢弃 |
| 参与方 | 用户、机器人（pipeline 调度 + Agent 执行 + 平台适配器） |

## 3. 端到端流程

```
时刻   用户行为                 系统行为                           用户看到
─────────────────────────────────────────────────────────────────────────────
T0    发"帮我写个脚本"          登记回合 v1，开始等静默              （无响应）
T0+1s 发"读取 csv"              同一回合，v2                        （无响应）
T0+2s 发"输出到 excel"          同一回合，v3                        （无响应）
T0+6s （停手满 4 秒）           关闭收集，定 v3 为当前回合
                               → 合并 3 条 → 一次 LLM 请求
T0+12s                                                    ←       收到一次完整回答
```

**被取代的情形**

```
T0    发"A"                     回合 v1 开始
T0+2s 模型开始回答 A             流式输出中
T0+3s 发"B"（补充/纠正）         v1 被取代：发停止信号；v1 已完成的部分不再发出
                               v2 成为当前回合
T0+9s （停手满 4 秒）           → 只回答 B（或 A+B 合并后的最新诉求）
```

**副作用工具的情形**

```
v1 在跑「查天气」工具
T0+3s 发"B" → v1 被取代
      但「查天气」已启动 → 让它跑完（不中途丢弃）
      → 结果存入回合共享槽位
v2 若也需要查天气（同工具同参数）→ 直接复用，不再重查
```

## 4. 状态与幂等规则

| 规则 | 业务含义 |
|---|---|
| 窗口 = 距最后一条 4s，距第一条最多 15s | 不会因为用户不停手而无限等待 |
| 已发出回复的回合不再吸收新消息 | 避免了"回答完又追加，结果又变"的混乱 |
| 同参工具只真执行一次 | 防重复发消息、重复计费、重复写库 |
| 已启动的操作必须完成一次 | 不做半途掐断，避免外部系统状态不一致 |
| 工具类进度消息不算"回复完成" | 回合可继续收集用户补充 |

## 5. 异常与边界

| 场景 | 表现 |
|---|---|
| 用户发完就不管了 | 静默 4 秒后正常回答 |
| 用户不停发超过 15 秒 | 15 秒硬上限到点就开始处理 |
| 用户发的第 2 条是 @别人 | 不并入本回合（视为对别人的话） |
| 图片 | 只取前 **2** 张并入（去重） |
| 机器人重启 | 回合状态全丢（纯内存），无残留影响 |
| 取消不彻底 | 旧请求可能仍消耗 token，但**产物一定不会发出** |
