# 维护保护与执行授权 · 技术全景

> `dashboard/services/plugin_service.py`（+17）、`tools/computer_tools/util.py`（+26）、

## 1. 维护保护

### 1.1 模块与职责

| 位置 | 角色 |
|---|---|
| `astrbot/core/star/maintenance.py` | 策略本体：`LocalMaintenanceProtectionError` + `assert_plugin_update_allowed(name, root_dir_name="")` |
| `star/star_manager.py` | 挂载点：`update_plugin()`（下载前）、`_install_plugin_from_directory()`（同名覆盖前） |
| `star/updater.py` | 挂载点：`_PluginUpdater.update()`（download 之前）——防绕过 `PluginManager` 直调 |
| `astrbot/dashboard/services/plugin_service.py` | UX 层：单个更新转 `PluginServiceError`；批量更新新增第三态 `"skipped"` |

### 1.2 判定逻辑

```
registry = get_astrbot_data_path() / "optimization_tracking/maintenance_registry.json"
  exists() == False              → 静默放行（fail-open）
  读取/结构异常                   → 抛错（fail-closed）      # 缺 key / 非 list / 元素非 str / JSON 坏
  name in protected_plugins      → 抛 LocalMaintenanceProtectionError
  root_dir_name in protected_plugins → 同上
  否则                           → 放行
```

### 1.3 Dashboard 侧

- 批量更新新增状态 `"skipped"`（不调用 `resolve_market_update_info`，省一次市场请求）。
- **顺带修了既有 bug**：同步 skills 的触发条件由 `len(failed) < len(results)`（非全失败才同步）
  改为 `any(r["status"] == "ok")`（有成功才同步），语义更准确。
- 小瑕疵：「全部成功」分支也会追加跳过提示，文案可能自相矛盾。

### 1.4 闸门覆盖矩阵

| 路径 | 是否受保护 |
|---|---|
| `PluginManager.update_plugin` | ✅ |
| `PluginManager._install_plugin_from_directory` | ✅ |
| `_PluginUpdater.update` | ✅ |
| `PluginService.update_plugin` / `update_all_plugins` | ✅ |
| **`uninstall_plugin`** | ❌ **未挂闸门** |
| **`install_plugin` / `install_plugin_from_file`** | ❌ 未挂闸门 |
| **启动器（外部进程）覆盖 core** | ❌ **完全拦不住**（无锁、无监听、无哈希校验） |

### 1.5 风险

| # | 风险 |
|---|---|
| R1 | **fail-open**：删掉 `maintenance_registry.json` 即绕过全部保护 |
| R2 | **卸载重装绕过**：`uninstall_plugin` 无闸门 |
| R3 | 拦截行为**无日志**（core 侧无 `logger` 输出，仅 Dashboard 有） |
| R4 | 每次调用全量读盘（调用频率低，可接受） |

## 2. 执行授权

### 2.1 模块与职责

| 位置 | 角色 |
|---|---|
| `code_delivery_policy.execution_denial(event, config)` | 判定本体，返回 `str | None`（`None`=放行） |
| `code_delivery_policy.apply_execution_policy(event, config, request)` | 装配期：不授权则摘 `EXECUTION_TOOL_NAMES` 并重建 `ToolSet`；并注入固定英文策略提示 |
| `tools/computer_tools/util.check_execution_permission(context, operation_name)` | 工具边界二次鉴权（带 `logger.info` 审计） |
| `tools/computer_tools/shell.py` / `python.py` | 4 个工具改用新闸门 |

### 2.2 判定逻辑

```
execution_denial(event, config):
  1. 身份：sender 必须在 config["admins_id"] 中            # 否则直接拒绝
  2. 意图：取当前消息 Plain 文本
        剔除 代码块 / 行内 code / 引用行
        按句切分
        命中祈使运行正则（运行|执行|编译并运行|^(please )?(run|execute)…）→ 该句授权
        命中排除式（不要运行 / 解释如何运行）→ 跳过该句
        任一句授权 → 放行；否则拒绝
```

### 2.3 两层防护

| 层 | 位置 | 时机 | 动作 |
|---|---|---|---|
| 1 | `apply_execution_policy` | LLM 请求装配期（`build_main_agent` 末尾） | 从 `ToolSet` 摘掉 4 个执行类工具 |
| 2 | `check_execution_permission` | 工具调用时（`get_booter()` 之前） | 再次鉴权，失败返回错误串并写审计日志 |

`EXECUTION_TOOL_NAMES = {astrbot_execute_python, astrbot_execute_ipython, astrbot_execute_shell, astrbot_shell_session}`

### 2.4 风险

| # | 风险 |
|---|---|
| R5 | **白名单硬编码**：第三方插件提供的执行类工具不在名单内 → 绕过策略 |
| R6 | **权限双模型并存**：`fs.py`、`cua.py`、`message_tools.py`、`shipyard_neo/*` 仍只用 `check_admin_permission`（不看意图），权限强度不一致 |
| R7 | **中文正则启发式**双向误判：误放行=提权风险；误拒绝=功能不可用（用户完全无法执行代码） |
| R8 | `allowed=True` 时**也无条件注入**固定英文 system prompt → 平白消耗 token、可能干扰非代码场景 |
| R9 | 拒绝时**无 warning 级审计日志**（安全事件留痕不足） |
| R10 | 持久 shell 会话：授权只看创建/操作那条消息，会话后续复用不再校验 |
| R11 | `config` 为 `None` 时 `config.get` 会 `AttributeError`（依赖调用方保证非 None） |
