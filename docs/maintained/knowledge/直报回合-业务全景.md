# 直报回合 · 业务全景

## 1. 为什么有这条链路

QQ 用户（`aiocqhttp` 平台）习惯**连发**：想到什么发什么，一条一句话。

在补丁之前，每条消息都是一次独立请求，于是出现三类可观察的故障：

| 现象 | 用户感受 | 根因 |
|---|---|---|
| 机器人对第 1 条、第 2 条、第 3 条各回一次 | 刷屏、答非所问 | 没有"这一串是一个人一口气说的"这个概念 |
| 前一条已经在跑了，用户又补一句 | 机器人把两件事都做了，或者先回答了作废的问题 | 在途请求无法撤销 |
| 副作用工具（发消息、写库、调外部 API）被重跑 | 重复发消息、重复计费 | 旧轮次的工具调用与新轮次各跑一遍 |

## 2. 参与方与术语

| 术语 | 含义 |
|---|---|
| **直报回合（direct turn）** | 同一账号在静默窗口内连发的多条消息，被视作**一个**请求 |
| **取代（supersede）** | 新消息到达时，把旧回合标记为作废（版本号 +1） |
| **当前回合（current）** | 版本号未被替换、且未被关闭、且未被显式取代的那个回合 |
| **工具结果复用** | 同参工具只真执行一次，被取代的旧回合已启动的操作结果可供新回合直接取用 |
| **静默窗口** | 距最后一条消息 `quiet_sec=4s`；距第一条消息上限 `max_wait_sec=15s` |

## 3. 能力地图

```
连发消息
   ├── 聚合成一轮            → 只回答最新的一条完整诉求
   ├── 取代旧轮次            → 旧结果不再发出去
   ├── 在途取消              → 旧请求尽量停下来（省 token）
   ├── 工具结果复用          → 同参工具不重复执行（防重复副作用）
   └── 出站门禁              → 即使取消不彻底，陈旧结果也不会发到群里
```

## 4. 端到端流程（用户视角）

1. 用户连发 3 条：`帮我写个脚本` → `读取 csv` → `输出到 excel`
2. 机器人**不立即回答**，等用户停手（约 4 秒静默）
3. 机器人把 3 条按到达顺序合并成一次请求，回答一次
4. 若用户在第 4 秒内又补第 4 条：前一次（已经开始了的）作废，机器人只回答含第 4 条的完整版
5. 若旧回合已经启动了某个工具（例如查天气），新回合**直接复用**它的结果，不再重查

## 5. 通用规则与边界

| 规则 | 说明 |
|---|---|
| **只对 `aiocqhttp` 生效** | `eligible()` 硬编码平台名；其他平台（微信/飞书/Telegram）走原路径，行为不变 |
| **必须有发送者** | 无 `sender_id` 的会话不参与合并 |
| **15 秒硬上限** | 用户一直不停手也不会无限等待 |
| **取消是协作式的** | 只是"请求停"，不保证真的中断 token 消耗；但产物一定被丢弃 |
| **已启动的操作必须完成一次** | 不做"执行到一半掐掉"，避免副作用状态不一致 |
| **工具类消息不标记已发送** | `tool_call` / `tool_call_result` 不算"回复完成"，回合可继续收集 |

## 6. 明确不做什么

- 不做跨平台统一回合抽象（当前只有 `aiocqhttp`）。
- 不做回合持久化（纯内存，进程重启即丢）。
- 不做"取消保证真正中断 provider 请求"（仅在 core 侧发停止信号）。
- 不改变非目标平台的任何行为。
