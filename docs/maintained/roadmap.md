## 3. 安全项：T8-10（提权误放行）—— ✅ **已完成（2026-10-17）**

以**模式化**收口：新增 `provider_settings.execution_gate_mode`，默认 `legacy`（上游 admin-only），
可选 `strict`（当前消息须明确要求运行）。默认改 legacy 后，`test_python_tools.py` 的
**11 项红全部转绿**；strict 模式内再加「转述标记」排除规则，修掉 4 例误放行。

- **内容**：`execution_denial` 误放行 —— 输入「文档里写：先编译，再运行」会被判为**授权执行**
  （授权分支缺主语约束，引用/转述即等于授权）。一并评估 `SAFETY_REFUSAL_PATTERN` 的漏判与误报。
- **现状态**：⛔ **严格暂缓，禁止在阶段 8 顺手改**；禁区 = `code_delivery_policy.py` **38–78**。
- **本规划的结论（2026-10-15 用户确认）**：排在**「转公开」之前**解决。理由 —— 提权误放行留着
  转公开，等于把一个已知的安全缺口带给社区用户，与「面向社区开源」的定位直接冲突。
- **紧迫度**：**低**。用户已确认公开是远期、条件驱动的事（见 §1），所以 T8-10 只需在
  「决定公开时」之前完成，不占用当前代码攻坚的注意力。

## 8. 未来规划：双模式（兼容模式 / 增强模式）

> **2026-10-16 用户定调**：默认 = **兼容上游 + 额外功能**；另设一个**增强模式开关**，
> 开启后允许改变插件的调用方式，追求效率与工整，并在开关下方以**红色下划线警告文字**
> 标注实验性风险。当前先做兼容模式。

### 8.1 两种模式的边界

| | **兼容模式（默认）** | **增强模式（可选开关）** |
|---|---|---|
| 定位 | 与原版逻辑**一致**，外加 additive 能力 | 追求效率与工整，允许改变调用方式 |
| 允许的优化 | **不影响逻辑**的整理：拆文件（行为等价）、把绕的逻辑改写成**效果与上游一致但更高效**的写法、纯性能优化 | 改写容易出错的调用路径、用更完善的优化逻辑替换原逻辑 |
| 不允许 | 任何改变外部可观察行为的改动 | — |
| 风险提示 | 无 | 开关下方红色下划线警告（实验性） |
