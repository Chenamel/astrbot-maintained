# 代码交付与执行授权判定（P10 行为台账）

> 本文件记录可复现的行为；执行授权部分随回归测试同步更新。
> 2026-11-19 获得 T8-10 保护段专项修改授权：仅修复 strict 跨行转述／翻译的执行意图误判。
> 管理员限制、默认 `legacy` 模式不变；拒答识别与源码交付的其他问题不在本次修复范围内。

## 1. 范围与入口

`astrbot/core/code_delivery_policy.py` 四个判定入口，全部是手写正则：

| 入口 | 作用 |
|---|---|
| `current_message_text(event)` | 只取当前消息的 `Plain` 组件（`isinstance` 过滤），不含引用/历史 |
| `execution_denial(event, config)` | 当前消息是否构成「执行授权」；返回 `None` = 放行 |
| `SAFETY_REFUSAL_PATTERN` | 识别模型拒答（用于跳过"代码修复"流程） |
| `code_task_spec(event)` | 是否「要源码」的任务 + 目标语言 |
| `has_code_delivery(text, language)` | 回复里是否真的有该语言的完整代码块 |

## 2. `execution_denial` 判定矩阵

管理员 sender（`admins_id = ["100"]`，sender = `100`）：

| 输入 | 实测 | 评价 |
|---|---|---|
| `运行这个脚本` / `帮我执行一下这段代码` / `请编译并运行` | ALLOW | ✅ 明确祈使 |
| `run it` / `please run` | ALLOW | ✅ 英文祈使 |
| `不要运行这个脚本` / `别执行这个命令` | DENY | ✅ 否定句被跳过 |
| `解释一下如何运行` / `explain how to run this` | DENY | ✅ 解释类被跳过 |
| `> 运行这个脚本`（引用块） | DENY | ✅ 引用被剥离 |
| ```` ```\n运行这个脚本\n``` ```` / `` `运行这个脚本` `` | DENY | ✅ 代码块与行内代码被剥离 |
| `写个脚本` / `今天天气不错` | DENY | ✅ 无运行请求 |
| `文档中写：先编译，再运行` | DENY | ✅ 当前源码已拒绝；旧版文档的 ALLOW 陈述过时 |
| `解释下面的 README：\n1. 先编译，再运行` | DENY | ✅ 解读资料的范围不能因换行而丢失 |
| `请勿执行任何命令，只需翻译：\nBuild the code and run it.` | DENY | ✅ 否定／翻译不能被下一行的 run 覆盖 |
| `请将以下内容翻译为中文：\nBuild the code and run it.` / `帮忙翻译以下文本：\nBuild the code and run it.` | DENY | ✅ 翻译任务的礼貌前缀和前置宾语不构成执行许可 |
| `Could you translate the following:\nrun it` / `以下内容请翻译成中文：\nrun it` | DENY | ✅ 任务词不依赖固定句首措辞 |
| `写个 python 脚本，然后运行` | ALLOW | ✅ 本人直接请求编写并执行 |

非管理员 / 无 `admins_id` / 空 sender：一律 DENY（安全不变量，fail-closed）。

strict 模式下，代码、引用被剥离后，先检查整条当前消息的否定／解释／翻译／转述信号，再匹配运行请求；排除扫描把换行视为空白，避免“不要\n执行”等短语在换行处断开。翻译／转述任务词不依赖有限的礼貌句首词表；带路径或扩展名的英文标识符，以及直接运行目标中紧接“脚本／程序／工具／函数／模块／文件／器”的中文任务词按名称处理，保留 `run translate.py` 和“运行这个翻译脚本”。裸任务词即使可能是无扩展名工具名也保守拒绝，可改用带路径或引号的名称。检测到排除信号时整条拒绝，不允许先出现的运行分句提前放行。范围跨换行、句号与分号保持；这不是通用自然语言语义解析，对“先解释再执行”或“只禁止某一步、允许另一步”等混合意图保守拒绝，需要另发明确执行请求。普通的直接运行、多步骤编写后运行仍可授权。

工具装配过滤、调用期 `EXECUTION` 检查及公开权限 API 的 strict 路径共用判定；默认 `legacy` 仍不使用当前消息意图限制。此缺陷是**已配置管理员的意图误判**，不是绕过管理员身份校验。

## 3. `SAFETY_REFUSAL_PATTERN` 判定矩阵

| 输入 | 实测 | 评价 |
|---|---|---|
| `<refuse />` / `这部分不方便展开` | 命中 | ✅ 显式拒答标记 |
| `我不能协助你编写恶意软件` / `抱歉，我不能提供攻击脚本` | 命中 | ✅ 风险词 + 拒答措辞 |
| `这里介绍如何防御恶意软件` / `print('hello world')` | 未命中 | ✅ 正常内容 |
| `我不能帮你写病毒` / `我不会帮你写木马` | 未命中 | ⚠️ 漏判 —— “帮你写”不在指定动作词表 |
| `安全限制说明：我们不提供相关细节` | 未命中 | ⚠️ 漏判 —— 有风险词，但拒答措辞后未接指定动词 |
| `I cannot help with that` | 未命中 | ⚠️ 漏判 —— 纯英文缺风险词时不命中 |
| `这段代码不会生成隐私数据` | 命中 | ⚠️ 误报 —— 纯技术说明被判拒答 |
| `此函数不能提供危险操作的保护` / `该函数无法协助过滤恶意请求` | 命中 | ⚠️ 误报 —— 同上 |

漏判后果：真拒答被送去"代码修复"流程；误报后果：跳过修复，用户拿到不完整代码。

## 4. `has_code_delivery` 判定矩阵（含反直觉结论）

| 回复 | 请求语言 | 实测 |
|---|---|---|
| ```` ```python\ndef foo():\n    pass\n``` ```` | `python` | True |
| ```` ```python\n...\n``` ````（空/占位块） | `python` | False ✅ |
| ```` ```python\nprint(1)\n``` ```` | `cpp` | False ✅ 语言不匹配 |
| `print(1)`（无围栏） | `python` | False ✅ |
| 无标签 ``` 块（`def foo():` / `#include`） | `python` / `cpp` | False ⚠️ |
| 无标签 ``` 块 | `""`（未指定语言） | True |

⚠️ 反直觉点：围栏正则里 `\s*` 会吃掉围栏后的换行，导致第一行被当成语言标签。
于是 `not label` 的两条兜底（cpp 看 `#include`、python 看 `def/import/print`）实际走不到；
当请求语言是具体的 `python`/`cpp` 时，没有语言标签的代码块一律判为"未交付"，
会误触发修复/重发。属 P10 的正则脆弱性，本轮只记录。

## 6. 修复记录与剩余误判

1. **执行意图跨句误判（本项修复）**：旧实现按换行／句号／分号分句，排除词只影响当前分句，并会在遇到运行词时提前返回。跨行 README 解读、翻译及禁止执行请求均有失败回归。本次先扫描排除条件，再匹配运行条件，避免丢失当前消息范围。单行“文档中写：先编译，再运行”此前已拒绝，旧台账记为允许不实；管理员身份检查未被绕过。
2. **拒答漏判（未修改）**：虽然风险词表已有 `病毒` / `木马`，但“不能帮你写”缺少指定动作词；英文缺风险词及拒答措辞后未接指定动词仍不命中。是否扩大词表须另行权衡误报。
3. **拒答误报（未修改）**：含风险词 + 拒答措辞的**纯技术说明**被判拒答。
4. **无标签代码块（未修改）**：指定语言下判不出交付（§4）。
