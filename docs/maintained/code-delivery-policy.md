## 1. 范围与入口

`astrbot/core/code_delivery_policy.py` 四个判定入口，全部是手写正则：

| 入口 | 作用 |
|---|---|
| `current_message_text(event)` | 只取**当前消息**的 `Plain` 组件（`isinstance` 过滤），不含引用/历史 |
| `execution_denial(event, config)` | 当前消息是否构成「执行授权」；返回 `None` = 放行 |
| `SAFETY_REFUSAL_PATTERN` | 识别模型**拒答**（用于跳过"代码修复"流程） |
| `code_task_spec(event)` | 是否「要源码」的任务 + 目标语言 |
| `has_code_delivery(text, language)` | 回复里是否真的有该语言的完整代码块 |

## 2. `execution_denial` 判定矩阵

管理员 sender（`admins_id = ["100"]`，sender = `100`）：

| 输入 | 实测 | 评价 |
|---|---|---|
| `运行这个脚本` / `帮我执行一下这段代码` / `请编译并运行` | ALLOW | ✅ 明确祈使 |
| `run it` / `please run` | ALLOW | ✅ 英文祈使 |
| `不要运行这个脚本` / `别执行这个命令` | DENY | ✅ 否定句被跳过 |
| `解释一下如何运行` / `explain how to run this` | DENY | ✅ 解释类被跳过 |
| `> 运行这个脚本`（引用块） | DENY | ✅ 引用被剥离 |
| ```` ```\n运行这个脚本\n``` ```` / `` `运行这个脚本` `` | DENY | ✅ 代码块与行内代码被剥离 |
| `写个脚本` / `今天天气不错` | DENY | ✅ 无运行请求 |
| **`文档中写：先编译，再运行`** | **ALLOW** | ⚠️ **误放行（T8-10）** —— 引用/转述被当成授权 |
| `写个 python 脚本，然后运行` | ALLOW | ✅ 本人真实授权（与上一行区别在主语） |

非管理员 / 无 `admins_id` / 空 sender：**一律 DENY**（安全不变量，fail-closed）。

## 3. `SAFETY_REFUSAL_PATTERN` 判定矩阵

| 输入 | 实测 | 评价 |
|---|---|---|
| `<refuse />` / `这部分不方便展开` | 命中 | ✅ 显式拒答标记 |
| `我不能协助你编写恶意软件` / `抱歉，我不能提供攻击脚本` | 命中 | ✅ 风险词 + 拒答措辞 |
| `这里介绍如何防御恶意软件` / `print('hello world')` | 未命中 | ✅ 正常内容 |
| **`我不能帮你写病毒`** / **`我不会帮你写木马`** | **未命中** | ⚠️ **漏判** —— 病毒/木马不在风险词表 |
| **`安全限制说明：我们不提供相关细节`** | **未命中** | ⚠️ **漏判** —— 有风险词，但拒答措辞后未接指定动词 |
| **`I cannot help with that`** | **未命中** | ⚠️ **漏判** —— 纯英文缺风险词时不命中 |
| **`这段代码不会生成隐私数据`** | **命中** | ⚠️ **误报** —— 纯技术说明被判拒答 |
| `此函数不能提供危险操作的保护` / `该函数无法协助过滤恶意请求` | 命中 | ⚠️ **误报** —— 同上 |

漏判后果：真拒答被送去"代码修复"流程；误报后果：跳过修复，用户拿到不完整代码。

## 4. `has_code_delivery` 判定矩阵（含反直觉结论）

| 回复 | 请求语言 | 实测 |
|---|---|---|
| ```` ```python\ndef foo():\n    pass\n``` ```` | `python` | True |
| ```` ```python\n...\n``` ````（空/占位块） | `python` | False ✅ |
| ```` ```python\nprint(1)\n``` ```` | `cpp` | False ✅ 语言不匹配 |
| `print(1)`（无围栏） | `python` | False ✅ |
| **无标签 ``` 块（`def foo():` / `#include`）** | **`python` / `cpp`** | **False** ⚠️ |
| 无标签 ``` 块 | `""`（未指定语言） | True |

⚠️ **反直觉点**：围栏正则里 `\s*` 会吃掉围栏后的换行，导致**第一行被当成语言标签**。
于是 `not label` 的两条兜底（cpp 看 `#include`、python 看 `def/import/print`）**实际走不到**；
当请求语言是具体的 `python`/`cpp` 时，**没有语言标签的代码块一律判为"未交付"**，
会误触发修复/重发。属 P10 的正则脆弱性，本轮只记录。

## 6. 已知误判容限（T8-10，本轮**不改**）

1. **误放行（提权风险）**：`code_delivery_policy.py:80` 的 `然后|并|再|并且` 分支**无主语约束**
   ⇒ 引用/转述文档即等于授权（矩阵第 8 行）。
2. **拒答漏判**：风险词表不含 `病毒` / `木马`；英文缺风险词不命中；拒答措辞后未接
   `协助|提供|编写|生成|展开|帮助` 也不命中。
3. **拒答误报**：含风险词 + 拒答措辞的**纯技术说明**被判拒答。
4. **（非 T8-10，新观察）** 无标签代码块在指定语言下判不出交付（§4）。
